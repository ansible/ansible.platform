# Controller and EDA migration contract coverage

**Snapshot:** 2026-11-12
**Scope:** Modules with changelog fragments identifying a migration from `awx_collection`, `awx.awx`, `ansible.controller`, or `ansible.eda`. Gateway-native modules are excluded.

This inventory is a working crosswalk, not a claim that every contract is covered. A target is listed only when its task file invokes the public migrated module. A target's presence does not establish API-boundary coverage.

The current API stack exposes the same resource transforms through `PlatformService` and `DirectHTTPClient`; the migrated resources below support the three integration modes: `local` and `http-direct` use `DirectHTTPClient`, while `http-persistent` uses `PlatformService`. The [integration workflow](../.github/workflows/integration.yml) runs the collection integration targets in all three modes. The shared request-construction tests are in [test_endpoint_request.py](../tests/unit/plugins/plugin_utils/platform/test_endpoint_request.py). The new [migration contract suite](../tests/unit/plugins/plugin_utils/api/test_migrated_resource_contracts.py) asserts create requests for 29 migrated resources, find and delete requests for 23 CRUD resources, unchanged-update idempotency and real-change PATCH bodies for all 22 updateable CRUD resources, create errors for every create fixture, update errors for all 22 updateable CRUD resources, delete 404/500 behavior for all 23 deleteable resources, and custom-action API errors. It also covers custom query, wait, singleton, direct-action, launch, and cancel contracts. Each API-boundary contract runs against both supported client implementations. The rows distinguish inapplicable operations from covered behavior.

## Coverage notes

- The new [migration contract suite](../tests/unit/plugins/plugin_utils/api/test_migrated_resource_contracts.py) calls the public client API and asserts resource-specific paths, methods, bodies, selected response transformations and result fields, API errors, and parity for the operations listed above. Both clients test unchanged-update no-ops, expected PATCH bodies, and API error propagation for all 22 updateable CRUD resources; all 23 deleteable resources test 404 no-op and 500 propagation. Existing resource transform tests cover additional API-to-Ansible mappings, including inventory and workflow nodes.
- The CI mode matrix provides module-level exercise in `local`, `http-direct`, and `http-persistent` modes for existing live integration targets. `local` and `http-direct` use `DirectHTTPClient`; `http-persistent` uses `PlatformService`. This mode matrix is not a substitute for focused request/response contract assertions.
- Existing integration task files invoke 44 of the 45 migrated modules; `subscriptions_test` is the exception, and the new `subscriptions_mock` scenario supplies its public-module smoke test. The other targets have varying lifecycle depth; the inventory distinguishes their presence from focused API assertions.
- Some named unit tests reach the HTTP boundary through internal methods such as `_find_resource` or `_execute_operations`. They are recorded as existing evidence, but should be replaced or supplemented with public-behavior tests when closing the listed gaps.
- `subscriptions` is a read-only singleton. Create/update/delete and idempotency do not apply; its observable contract is the credential POST, transformed subscription list, client-side filtering, and errors.
- The `subscriptions_test` integration target is retained as a live-test scaffold because CI lacks Red Hat subscription credentials. The new `subscriptions_mock` scenario exercises the public module against the mock API without external credentials.
- Target inventory is based on tracked task-file references and migration changelog fragments in this checkout. Reconcile the list when additional migrations land.

## Singleton audit (AAP-102076)

This PR covers the public SDK contracts for `subscriptions` and `license`.
Gateway `settings` and Controller `controller_settings` are tracked by
[AAP-102130](https://redhat.atlassian.net/browse/AAP-102130), related
to [AAP-102076](https://redhat.atlassian.net/browse/AAP-102076). Unchanged-subset
writes, Controller `name`/`value` conversion, and stopping on settings read
failures are outside this PR and are not fixed here.
